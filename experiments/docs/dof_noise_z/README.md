# 实验：给参考帧的部分关节加噪声，goal z 变化多少

- 日期：2026-10-20
- 脚本：`experiments/dof_noise_z.py`（单测 `tests/test_dof_noise_z.py`）
- 模型：`new_model_for_training_code_inference`（z_dim 256，z 在半径 √256 = 16 的球面上）
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作
- 原始结果：本目录 `metrics.json`、`summary.csv`（按组 × N × σ）、`per_joint.csv`（单关节），
  `samples.npz`（全部样本，53 MB，已 gitignore，只在本地）。脚本默认就输出到本目录

## 1. 问题

`motion_to_z` 看的是数据集中自然出现的两帧之间 z 差多少。这里改成人为的、可控的扰动：
从动作集中随机取一帧，只改上肢、下肢或任意部位的 N 个关节角，看 z 变化多少。
想回答：z 对哪些关节敏感？同样改 N 个关节，上肢和下肢谁影响大？改关节和自然的动作变化相比，z 的反应一样吗？

## 2. 设置

- **帧**：从运动库存储的原始帧（30 fps，不插值）中随机取 2,000 帧。
- **关节组**：
  - `upper`：两臂 14 个关节（肩 3 + 肘 1 + 腕 3，左右各一组）
  - `lower`：两腿 12 个关节（髋 3 + 膝 1 + 踝 2，左右各一组）
  - `any`：全部 29 个关节，含腰部 3 个
  - 机器人配置中 `upper_dof_names` 和 `lower_dof_names` 都包含腰部 3 个关节。为了让"上肢 / 下肢"互不重叠，两组都去掉了腰部；
    腰部只出现在 `any` 组和单关节分析中。
- **噪声**：每个样本从组内无放回地随机选 N 个关节，加 N(0, σ²) 的噪声，再截断到关节限位。
  N ∈ {1, 2, 4, 8, 12}，σ ∈ {0.05, 0.1, 0.2, 0.4} rad（约 3°、6°、11°、23°），每帧每种组合重复 4 次，每组 80,000 个样本。
- **B 的输入**：用运动库的正向运动学（`Humanoid_Batch.fk_batch`）从加噪后的关节角重新算出全部刚体的位置和朝向，
  根节点位置和朝向不变，**所有速度保持原值**。再用与 `get_backward_observation` 相同的代码
  （拆出的 `humanoidverse.utils.helpers.backward_observation_from_state`）构造观测，z = `project_z(B(obs))`。
  干净帧的 z 也经过同一条正向运动学计算，所以差异只来自噪声。
- **自检**：干净帧经正向运动学得到的刚体位置与运动库存储值的最大误差为 1e-6 m；
  由此算出的 z 与直接用存储值算出的 z 余弦为 1.0000（最小 0.99999988）。
- **消融（通道）**：B 的输入由两部分组成：`state`（关节角、关节速度、重力投影、根角速度）和
  `privileged_state`（由刚体位置、朝向、速度算出）。除完整扰动（`full`）外，还试了只把噪声放进其中一部分：
  `state` 只改关节角、刚体不变；`privileged` 只改刚体、关节角不变。

运行命令（约 1 min）：

```bash
uv run python -m experiments.dof_noise_z --model-folder new_model_for_training_code_inference
```

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| `z_cos` | 加噪帧与干净帧的 z 余弦（默认为 `full` 通道） |
| `z_cos_state` / `z_cos_privileged` | 只把噪声放进 `state` / `privileged_state` 时的 z 余弦 |
| `d_dof` | 29 个关节角的 RMSE（rad），截断后的实际改变量 |
| `d_pose` | 30 个刚体相对根节点的位置变化的平均（m），定义同 `motion_to_z` |

## 5. 推论

1. **腰部是 z 最敏感的关节，远超其他关节。** σ = 0.2 时，单独改一个腰部关节，z 余弦降到 0.86–0.91；
   其余 26 个关节都在 0.975 以上。改 1 个腰部关节的效果，大约相当于同时改 4–12 个四肢关节（对照 4.1 节同一 σ 的 upper、lower 行）。
   腰部转动会带动整个上半身（`d_pose` 1.2–1.7 cm，是单关节里最大的），而且 B 的输入里身体朝向相关的量都随之改变。
2. **按关节数和弧度算，下肢比上肢影响大。** 同样的 N 和 σ，lower 的 z 变化总是大于 upper
   （例如 N=4、σ=0.2：0.937 对 0.951；N=12、σ=0.4：0.598 对 0.638）。
   其中髋关节最敏感（0.975–0.981），膝和踝反而不敏感（≥ 0.988）。
3. **按身体位移算，上肢反而更敏感。** 同样移动 1–2 cm，改上肢后 z 余弦是 0.888，改下肢是 0.932。
   原因是同样的位移，上肢需要更大的关节角改变（d_dof 0.113 对 0.073）。z 与 d_dof 的相关（Spearman 约 0.94）
   明显高于与 d_pose 的相关（0.80–0.86）：**z 跟踪的是关节角本身，而不只是身体在空间中的位置。**
   最明显的例子是腕 pitch：几乎不移动任何刚体（0.03 cm），z 余弦却降到 0.975，和髋关节一样。
4. **人为加噪比自然动作更能改变 z。** 身体位移相同时，关节噪声造成的 z 差距（1 − cos）约为自然动作的 2–3 倍
   （位移约 1.4 cm 时 0.073 对 0.032；约 0.7 cm 时 0.028 对 0.009）。而且加噪时速度完全没变，自然动作的速度却是变化的。
   推测是加噪后的姿态（例如两臂各关节随机扭动）不在训练数据的分布里，B 对这种组合反应更大（未核实）。
5. **只扰动一半输入，z 变化反而更大。** 只改 `state` 的关节角或只改 `privileged_state` 的刚体时，
   z 的变化都比两者一起改更大（例如 any、N=4、σ=0.2：full 0.908，state 0.872，privileged 0.847）。
   这两种输入前后矛盾（关节角说手臂在这儿，刚体位置说在那儿），在训练中从未出现过。
   所以这个消融不能读成"哪个通道贡献了多少"；能说的只是两部分输入都会让 z 明显变化，而且 B 对不一致的输入很敏感。
6. **越稳定、越常见的动作，z 对噪声越敏感。** walk、sprint 的 z 变化最大，fallAndGetUp 最小。
   可能是 walk 一类的姿态在数据中很密集，B 在这附近分得更细（未核实）。

## 6. 给人看的结论

- 只改一个腰部关节 11°，z 的余弦就降到约 0.86；改一个髋关节 11° 约 0.98，改膝、肘、踝几乎不变（约 0.99）。
- 同样改几个关节、改同样的角度，改腿比改手臂对 z 影响大；但如果比的是"身体位置挪动了多少"，改手臂的影响反而更大。
  z 更像是在记录关节角度，而不是身体各部位在空间中的位置。
- 全身 12 个关节各随机改约 6°，z 余弦就到 0.92 左右。结合 `z_to_motion`，这个量级的 z 差异
  会让执行 1 秒后的轨迹平均差 8–9 cm。
- 人为加的噪声比自然的动作变化更能改变 z：身体挪动同样的距离，噪声造成的 z 差异是自然动作的 2–3 倍。

## 7. 误区澄清

**误区 1："`state` 和 `privileged` 两列的 z 变化都比 `full` 大，说明两个通道的效应互相抵消。"**
不对。单通道扰动产生的是自相矛盾的输入，属于分布外的样本，不是 `full` 扰动的一个"分量"（推论 5）。

**误区 2："腕关节、踝关节的 d_pose 为 0，说明它们不影响身体。"**
`d_pose` 只看 30 个刚体原点的位置，腕和踝转动时下游刚体原点几乎不动，但朝向变了，B 的输入里的刚体朝向和关节角也变了。
所以 z 仍会变化（腕 pitch 0.975）。

**误区 3："lower 比 upper 敏感，所以腿更重要。"**
只在"相同关节数、相同弧度"下成立。按身体位移比，结论相反（推论 3）。而且最敏感的腰部不在这两组里。

**误区 4："σ = 0.4 时余弦 0.5–0.6，说明 z 已经完全不同了。"**
σ = 0.4 rad 约 23°，同时改 8–12 个关节已经是很大的姿态改变（d_pose 4–7 cm），而且大多不是自然姿态。
`motion_to_z` 中随机两帧的 z 余弦平均只有 0.11，所以 0.5–0.6 仍然算"相关"。

## 8. 局限与后续

- 速度保持不变，所以加噪帧在速度上与原帧一致、在姿态上不一致，这本身就是一种不自然的状态。
- 噪声只加在关节角上，没有加在根节点的朝向和高度上。
- 只看了 z 的变化；这些 z 交给 actor 后的行为差异，可以用 `z_to_motion` 的框架（把加噪后的 z 作为扰动）进一步测。
- 推论 4 和 6 的解释未核实。
