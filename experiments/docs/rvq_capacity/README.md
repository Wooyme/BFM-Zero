# 实验：残差 VQ 能把 goal z 还原到多准，需要多少 token

- 日期：2026-10-20
- 脚本：`experiments/rvq_capacity.py`（单测 `tests/test_rvq_capacity.py`）
- 模型：`new_model_for_training_code_inference`（z_dim 256，z 在半径 16 的球面上）
- 数据：`latent_vq/goal_z.npz`（`humanoidverse/latent_vq/extract.py` 的输出），40 个 LAFAN 动作共 441,120 帧的 goal z（T=1，保留速度）
- 原始结果：本目录 `metrics.json`、`rate_distortion.csv`，`codebooks.npz`（残差 k-means 码本，`rvq_rollout` 会用到，已 gitignore）
- 配套的闭环实验：`rvq_rollout`

## 1. 问题

前面三个实验说明：actor 对 z 很敏感（余弦 0.98 时 1 s 后差约 5 cm），z 主要编码关节角和速度。
`latent_vq` 目前用残差 VQ（RVQ）把每帧的 z 变成 token。这里问 RVQ 的可行性：

1. 不考虑 encoder 的学习难度，**残差码本本身**能把 z 还原到多准？精度随 token 预算怎么增长？
2. 在没见过的动作上还剩多少？
3. 现有的 `LatentRVQVAE` 达到了这个上限的多少？
4. token 序列在时间上有多稳定、多好预测？这关系到后续能否在 token 上训练策略或先验。

## 2. 设置

- **训练 / 留出划分**：与 `latent_vq` 已有的 runs 相同，留出 4 个动作
  `fallAndGetUp1_subject5`、`jumps1_subject1`、`run2_subject1`、`walk2_subject1`（共 45,080 帧）。所有码本只用训练帧拟合。
- **残差 k-means（rkm）**：没有 encoder / decoder 的 RVQ。第 1 层是 z 的 k-means，第 i 层是前 i−1 层剩下的残差的 k-means
  （每层从 20 万个训练帧拟合，20 轮迭代）。编码时逐层取最近的码，还原时把前 d 层的码相加后投影回球面。
  K ∈ {16, 64, 256, 1024}，深度 d = 1..8，每帧 d·log₂K bit。
- **对照**：
  - `learned`：`latent_vq` 下已训练的 `LatentRVQVAE`（K=256、2 层，chunk 1–32），用前 1 层或 2 层 token 还原；
    chunk > 1 时一组 token 代表 chunk 帧，所以每帧的 bit 数要除以 chunk
  - `flat_kmeans`：4096 个中心的普通 k-means（12 bit）
  - `pca`：用训练帧的前 d 个主成分重建，衡量 z 的"线性维度"
  - `nearest_other_motion`：训练集中**另一个动作**里 z 最近的那一帧，相当于"用别的动作的帧当码本"
  - `previous_frame`：同一动作的上一帧（20 ms 前），作为"差一帧"的参照
- **序列统计**：在训练动作的相邻帧上，统计 token（或 token 元组）多久换一次（切换率、平均持续帧数），
  以及已知当前 token 时下一个 token 的条件熵 H(next | current)。

运行命令（约 35 s，不需要 Isaac）：

```bash
uv run python -m experiments.rvq_capacity --model-folder new_model_for_training_code_inference
```

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| `cos_mean` / `cos_p5` | 还原的 z 与原 z 的余弦，均值 / 5% 分位数 |
| `frac>=c` | 余弦 ≥ c 的帧所占比例 |
| bits | 每帧的 token 信息量：d·log₂K，chunk > 1 时再除以 chunk |

参照（来自前面的实验）：`z_to_motion` 中，随机方向的余弦 0.98 / 0.95 / 0.9 / 0.8，会让 1 s 后的轨迹平均差
5.2 / 7.1 / 9.4 / 13.4 cm；`motion_to_z` 中，同一动作相隔 1 / 2 / 5 帧的余弦是 0.991 / 0.968 / 0.843。

## 5. 推论

1. **z 几乎是满秩的。** 64 个主成分只解释 49% 的方差，192 个主成分（3/4 的维度）重建留出集也只有 0.925。
   z 的信息分散在几乎全部 256 维里，而不是集中在一个低维流形上。这从根本上限制了任何离散码本的精度。
2. **按"重建余弦"的标准，RVQ 远达不到 actor 需要的精度。** 最大的配置（K=1024、8 层、80 bit/帧）在训练集上只有 0.899，
   留出集上 0.783；留出集上没有任何配置能让任何帧达到 0.98。作为对照，"差一帧"就有 0.99，
   而 0.98 是 actor 1 s 后偏离约 5 cm 的水平。
3. **精度随 token 预算增长得很慢。** K=256 时每加一层（8 bit），留出集余弦在第 4 层之后只提升约 0.015–0.02；
   1 − cos 从 1 层到 8 层只从 0.46 降到 0.25（约减半）。照这个速度外推，要到 0.98 需要远超 100 bit/帧
   （外推，未验证）。
4. **泛化差距很大，而且主要不是码本的问题。** 训练集中另一个动作里最近的帧，余弦也只有 0.69（训练集和留出集都一样）。
   也就是说不同动作的 z 本来就离得很远，没见过的动作的 z 在训练数据里找不到近邻。
   RVQ 是组合式的，可以比"最近帧"做得好（K=1024、d=8 留出 0.78），但仍然有限。
5. **现有的 `LatentRVQVAE` 不比无 encoder 的残差 k-means 好，泛化更差。** 同样 16 bit，learned chunk1 训练 0.700 对 rkm 0.713，
   留出 0.496 对 0.608；而且尾部差得多（p5 0.13 对 0.41）。encoder/decoder 没有带来更紧凑的表示，反而加重了过拟合。
   chunk 越大越差，chunk 32 时留出只有 0.395。
6. **粗层 token 在时间上很稳定，细层 token 几乎每帧都不同。** K=256 的第 1 层 token 平均持续 12 帧（0.25 s），
   下一个 token 很好预测（0.69 bit）。但前 4 层的元组在 40 万训练帧里有 14.7 万种，平均 2.4 帧就换一次，几乎没有复用。
   要达到更高精度就要更多层，而更多层意味着 token 序列更像连续值，失去了离散化的意义。

## 6. 给人看的结论

- goal z 的 256 维几乎都在用，没有明显的低维结构，所以把它压成少量离散 token 一定会丢很多信息。
- 即使每帧用 80 bit（8 个 1024 选 1 的 token），在新动作上也只能还原到余弦 0.78。而机器人对 z 的要求是 0.98 左右。
- 现有的 RVQ-VAE 在新动作上只有 0.50，比直接对 z 做残差 k-means 还差。
- 但重建余弦不等于机器人做得好不好：actor 的敏感方向只有约 3 个。真正的可行性要看 `rvq_rollout` 的闭环结果。

## 7. 误区澄清

**误区 1："训练集余弦 0.9 说明 tokenizer 学得不错。"**
训练集上是记忆，留出集才说明能否用于新动作；两者差 0.1–0.2。而且平均值掩盖了尾部：learned chunk1 有 5% 的帧余弦低于 0.25。

**误区 2："chunk 越大，每帧 bit 越少，越划算。"**
bit 少是因为一组 token 只能代表 chunk 帧的平均状态。表中 chunk 32 的每帧精度最低，并没有"白赚"。

**误区 3："重建余弦低，tokenizer 就一定不能用。"**
不一定。z 的误差有多少会被 actor 放大，取决于误差落在哪些方向（`z_to_motion`：敏感方向只有约 3 个）。
重建余弦只是必要条件的一个粗略代理，闭环效果要看 `rvq_rollout`。

**误区 4："PCA 192 维 0.925，那降到 192 维再量化就行。"**
192 维仍然是连续向量。降维只去掉了 1/4 的维度，不能解决离散化的问题。

## 8. 局限与后续

- 只在 T=1 的 goal z 上测试；T=8 的 tracking z 更平滑，率失真曲线可能更好。
- 残差 k-means 没有在码本拟合中考虑 actor 的敏感度。如果按 actor 的雅可比给误差加权（只量化 actor 在乎的方向），
  需要的 bit 数可能少得多，这是值得尝试的方向。
- 第 3 点的外推未验证。
