# 实验：参考动作帧之间的差异，在 goal z 上体现成多大

- 日期：2026-10-20
- 脚本：`experiments/motion_to_z.py`（单测 `tests/test_motion_to_z.py`）
- 模型：`new_model_for_training_code_inference`（z_dim 256，z 投影到半径 √256 的球面）
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作，共 441,120 帧（50 Hz）
- 原始结果：本目录 `metrics.json`、`pairs_summary.csv`（分箱表）、`collisions.csv`（z 近、姿态远的帧对），
  `pairs.npz`（全部帧对，129 MB，已 gitignore，只在本地）。脚本默认就输出到本目录

## 1. 问题

`tracking_window` 发现：z 余弦 0.93 时，执行出来的动作差别已经很明显。这里反过来问：
**参考动作本身**差多少，z 才差这么多？z 主要反映动作的哪些方面？"z 很近、动作却很远"的情况有多常见？

本实验只看参考动作和 z，不做 rollout。z 经 actor 执行后的变化见 `z_to_motion`。

## 2. 设置

- **z(f)** = `project_z(B(next_obs[f]))`，即每帧的 goal z（T=1），速度保留（`velocity_multiplier = 1`）。
  与当前 `latent_vq` 的 tokenize 对象一致。
- **每帧的动作特征**：
  - `pose`：30 个刚体相对根节点的位置，转到根节点的航向坐标系（只去掉 yaw，保留俯仰和横滚）
  - `dof`：29 个关节角；`dof_vel`：关节速度
  - `root_vel`、`ang_vel`：根节点线速度、角速度，转到航向坐标系
  - `height`：根节点高度
- **三类帧对**：
  - 随机对：在全部帧中随机抽 100 万对
  - 时间对：同一动作内相隔 Δ = 1, 2, 5, 10, 25, 50 帧的所有帧对
  - 近邻对：每 5 帧取一个查询帧（88,224 个），在全部帧中找 z 余弦最大的 10 个近邻（`z_nn`），
    以及 pose 欧氏距离最近的 10 个近邻（`pose_nn`）。两者都排除同一动作 ±25 帧以内的帧，避免找到的只是相邻帧
- **线性探针**：用 ridge 回归从 z 预测各项动作特征。40 个动作分成 5 折，按动作留出做交叉验证，报告留出集的 R²

运行命令（约 40 s）：

```bash
uv run python -m experiments.motion_to_z --model-folder new_model_for_training_code_inference
```

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| `z_cos` | 两帧 z 的余弦相似度 |
| `d_pose` | 两帧 `pose` 的 30 个刚体平均位置距离（m）。去掉根平移和 yaw 后的姿态差 |
| `d_dof` | 关节角 RMSE（rad） |
| `d_root_vel` / `d_ang_vel` | 航向坐标系下根节点线速度差（m/s）/ 角速度差（rad/s）的模 |
| `d_height` | 根高度差（m） |
| `d_dof_vel` | 关节速度 RMSE（rad/s） |
| 碰撞率 | z 近邻对中，`d_pose` 超过某个阈值的比例。阈值取随机对 `d_pose` 的中位数（12.5 cm），或同一动作相隔 25 帧时的中位数（7.9 cm） |

## 5. 推论

1. **从参考动作这一侧看，z 近基本等于动作近。** 三类帧对的"z_cos → d_pose"关系几乎重合
   （z_cos 0.9–0.95 时 d_pose 都约 2 cm，0.98 以上约 0.7 cm）。z_cos ≥ 0.9 的近邻对中，
   只有 0.67% 的姿态差超过相隔 25 帧的典型差距，0.15% 超过随机两帧的典型差距。
   所以"z 差不多、动作差很多"的现象，主要不是因为 z 把不同的参考动作映射到了一起。
2. **goal z 变化得很快。** 相邻 1 帧的 z_cos 是 0.991，2 帧 0.968，5 帧（0.1 s）就降到 0.843，10 帧 0.63。
   拿 `tracking_window` 来对照：T=1 和 T=8 的 z_cos 是 0.927，按 4.3 节插值，大致相当于参考动作相隔约 3 帧（约 2 cm 的姿态差）。
   也就是说，那次实验里 0.927 的 z 差异，对应的参考动作差异其实很小，但执行结果差了 6 cm，放大发生在 actor 一侧。
3. **z 同时编码姿态和速度。** pose 近邻（姿态最像的帧）的 z_cos 只有 0.61，q10 低至 0.21；
   它们的速度差（root_vel 0.49 m/s、ang_vel 1.02 rad/s）比 z 近邻（0.28、0.67）大得多。
   线性探针也显示 z 能很好地预测根速度（R² 0.90）。姿态相同、速度不同的两帧，z 可以差很远。
4. **z 与关节角的关系最紧。** 在 z 近邻里，d_dof 的 Spearman（−0.80）和偏 R²（0.053）都最高，
   其余各项的偏 R² 都很小，说明它们的信息大多已包含在 d_dof 里。在随机对里，d_pose 和 d_dof 并列第一。
   根高度在随机对里相关明显（因为站着和躺着的帧差别很大），但偏 R² 几乎为 0。
5. **z 线性编码了姿态、根速度和高度，没有很好地编码关节速度。** 关节速度的 R² 只有 0.33；
   d_dof_vel 在随机对上与 z 距离的相关性也弱（Spearman −0.25）。
6. **少数"碰撞"集中在 fallAndGetUp 和 jumps。** z_cos ≥ 0.9 却姿态差 > 7.9 cm 的比例：
   fallAndGetUp 4.8%、jumps 2.7%，其余类别 ≤ 0.4%。这些帧对的关节角差和速度差都不大，
   姿态差可能主要来自根节点的俯仰或横滚（`pose` 只去掉了 yaw，躺在地上时朝向的微小差别会放大到全身刚体位置）。
   这一点**未核实**。

## 6. 给人看的结论

- 从参考动作看，z 很近（余弦 ≥ 0.9）的两帧，姿态通常只差约 2 cm；z 近而动作远的情况不到 1%，
  主要出现在摔倒爬起和跳跃里。
- goal z 对时间很敏感：只隔 0.1 s，余弦就从 1 掉到约 0.84。z 余弦 0.93 大约相当于参考动作相隔 3 帧。
- z 不只反映姿态，也反映速度：姿态一样但运动方向或快慢不同，z 会明显不同。
- 所以"z 差异不大时动作也可能差异很大"，主要不是 z 把不同动作编码到了一起，而是 actor 把小的 z 差异放大了，
  见 `z_to_motion` 实验。

## 7. 误区澄清

**误区 1："z 近邻和 pose 近邻重合率只有 23%，说明 z 不反映姿态。"**
不对。z 近邻的平均姿态差只有 4.0 cm，接近 pose 近邻的最优值 3.0 cm。重合率低是因为
同一姿态附近有很多帧，z 会按速度把它们区分开（推论 3），而 pose 近邻不管速度。

**误区 2："随机对的线性 R² 只有 0.41，说明 z 与动作差异关系不大。"**
随机对几乎都是 z_cos < 0.4 的远距离对，到了这个范围，z 距离基本饱和，动作再怎么不同，余弦也只在 0 附近波动
（`d_pose` 十分位从低到高，z_cos 均值只从 0.23 降到 0.01）。近距离的关系要看 z 近邻（R² 0.63、Spearman 0.80），
这才是 VQ 量化、近邻检索真正关心的范围。

**误区 3："碰撞对是 z 的编码错误。"**
不一定。这些对 97% 来自同一动作，关节角和速度都接近，差别主要在 `pose` 上，很可能是躺姿或腾空时根节点
俯仰、横滚的差异（未核实）。B 的输入是否包含、以及以多大权重包含这些量，决定了 z 是否应该区分它们。

**误区 4："z_cos 0.9 → 姿态差 2 cm，所以执行误差也该是厘米级。"**
本实验只回答参考动作之间的距离。z 交给 actor 后会被放大多少，是 `z_to_motion` 要回答的问题，两者不能互相代替。

## 8. 局限与后续

- 只测了一个模型、T=1 的 goal z。T=8 的 tracking z 变化更平滑，数字会不同。
- `pose` 只去掉了 yaw，躺姿和腾空时根节点俯仰、横滚的差异会计入 `d_pose`。可以再加一个去掉完整根朝向的版本，
  用来核实推论 6。
- 线性探针只能说明信息能否被线性读出；R² 低不代表 z 里没有这项信息。
- pose 近邻用的是展平坐标的欧氏距离，和 `d_pose`（逐刚体距离的均值）不完全相同。
