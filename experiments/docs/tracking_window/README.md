# 实验：tracking 窗口 T 对 latent z 与策略执行的影响

- 日期：2026-10-20
- 脚本：`experiments/tracking_window.py`（单测 `tests/test_tracking_window.py`）
- 模型：`new_model_for_training_code_inference`（训练 `seq_length = 8`，z_dim 256）
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作
- 原始结果：本目录 `metrics.json`、`per_motion.csv`、`rollouts.npz`（逐步数据，400 MB，已 gitignore，
  只在本地）。脚本默认就输出到本目录

## 1. 问题

`latent_vq` 目前对每帧 goal z（T=1，保留速度）做 tokenize，而模型训练时的 tracking z 用的是 8 帧窗口。
问题：不同窗口 T 得到的 z 差多少？这些差异经 actor 执行后，动作和轨迹又差多少？

## 2. 设置

- **z_T(f)** = `project_z(mean B(next_obs[f : f+T]))`，T = 1..8，速度保留（`velocity_multiplier = 1`），
  窗口在动作末尾截断。T=1 即逐帧 goal z，T=8 即训练时的 tracking z。
- **起点**：每个动作每 10 帧取一个起点 t（须满足 t+50 仍在动作内），共 43,926 个。
- **初始状态**：参考帧 t 的根节点位置、朝向、线速度、角速度，以及关节位置和速度（`reset_envs_idx`，
  与 `humanoidverse/tracking_inference.py` 相同的流程）。
- **执行**：actor 均值动作 `model.act(obs, z, mean=True)`，闭环 50 步（1 s，50 Hz）。
  z 按 tracking 的方式滑动更新：第 k 步动作用 z_T(t+1+k)。
- **并排对照**：同一起点的所有 T 在相邻 env 中从同一状态出发。窗口列表为 `1 1 2 3 4 5 6 7 8`，
  第二个 T=1 是复跑，用于测仿真噪声底。
- 关闭域随机化和观测噪声，所有 termination 关闭（运行时断言没有任何 env 被重置）。

运行命令：

```bash
uv run python -m experiments.tracking_window --model-folder new_model_for_training_code_inference \
    --windows 1 1 2 3 4 5 6 7 8 --num-envs 1017
```

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| `z_cos_base` / `z_cos_last` | 同一步 z_T 与 z_1 / z_8 的余弦相似度 |
| `open_loop_action` | 第 0 步动作与 T=1 动作之差的 L2（29 维归一化动作）。此时各 T 的观测完全相同，只有 z 不同，衡量的是**网络本身**对 z 的敏感度 |
| `action_base` | 闭环 50 步中每步动作差的平均。包含状态分叉的影响 |
| `body_base@k` | 第 k 步时与 T=1 rollout 的 30 个刚体平均位置距离（m） |
| `body_ref` | 与**参考帧 t+1+k** 的 30 个刚体平均位置距离，世界坐标、不对齐，含根漂移；对 50 步、全部起点取平均 |
| `body_ref_local` | 同上，但两边各自减去根节点位置（去平移，不去朝向） |
| `dof_ref` | 29 个关节角相对参考帧的 RMSE（rad） |
| `lost` | 50 步内任一步 `body_ref` > 0.5 m 的比例（评估用的 `terminate_when_motion_far` 阈值） |

## 5. 推论

1. **z 在隐空间里随 T 平滑变化。** 相邻 T 的余弦都是 0.998，T=1 到 T=8 也有 0.927。余弦矩阵呈带状，
   差异随 |T − T'| 单调增大，说明窗口均值是一个连续的平滑过程，没有突变。
2. **actor 对这点 z 差异很敏感。** z 余弦只降到 0.927，同一观测下的动作差却达到噪声底的约 9 倍
   （0.211 对 0.024），闭环 1 s 后的轨迹差约为噪声底的 6 倍（6.4 cm 对 1.0 cm）。
3. **z 差距可以预测行为差距。** Spearman 0.76，各类别都在 0.70–0.81。z 差得越多，执行差得越多，
   而且这个关系不依赖动作类型。
4. **在滑动更新 z 的 tracking 方式下，T 越大，逐帧跟踪参考越准。** 全局身体误差、根相对误差、
   关节 RMSE、丢失率四项随 T 单调下降，T=8（训练窗口）最好；80.5% 的起点上 T=8 优于 T=1。
   提升幅度为 10–30%，方向一致但量级不大。
5. **误差差距随时间拉开。** 第 1 步时 T=1 与 T=8 几乎相同，到第 50 步全局误差差 2.2 cm、
   根相对误差差 1 cm。说明长窗口 z 的好处体现在持续的闭环跟踪中，而不是单步动作的精度。
6. **快速动作受益最大。** run 的丢失率从 17.1% 降到 11.9%，根相对误差下降约 20%；
   dance 和 run 的 z 差距也最大（余弦约 0.89）。walk 的 z 差距最小，但相对提升仍有 10% 左右。

## 6. 给人看的结论

- 用 8 帧窗口算 z，比逐帧算 z 跟踪得更好：误差小约 10%，摔倒或跟丢的情况少约 30%。
- z 看起来差不多（余弦 0.93），但机器人的动作会明显不同。不能用"z 很接近"来推断"动作也差不多"。
- 对 `latent_vq` 的建议：tokenize 的目标可以考虑从 T=1 的 goal z 换成 T=8 的 tracking z，
  与训练和最佳执行效果保持一致。

## 7. 误区澄清

**误区 1："T 越大，仿真中的动作越像 T 帧的参考轨迹。"**
本实验不支持这个说法。`body_ref` 每一步只和参考的下一帧 t+1+k 比较，比较对象与 T 无关；
而且 z 每一步都会换成新窗口的值。z_T 是 T 帧 B 的平均，只是一个向量，不是一段轨迹，
policy 不会把它当作"一段 T 帧动作"来执行。能说的是：**在每步更新 z 时，T 越大，逐帧跟踪参考越准**，
可以理解为 z 带上了未来几帧的信息。要验证"一个 z 能否代表一段 T 帧"（VQ chunk token 真正关心的问题），
需要另做实验：固定一个 z_T(t) 执行 T 步，再与参考帧 t+1..t+T 逐帧比较（见第 8 节）。

**误区 2："对参考的身体误差就是姿态误差。"**
`body_ref` 是世界坐标下的距离，含根节点平移漂移，并且漂移会随步数累积
（全局误差在第 50 步约 20 cm，根相对误差只有约 6 cm）。只关心姿态时看 `body_ref_local` 或 `dof_ref`；
三者在本实验中趋势一致。

**误区 3："复跑同一个 T=1，差异应该是 0。"**
实测不为 0：首步动作差 0.024，50 步后轨迹差约 1 cm。可能的原因是 GPU 物理的不确定性，
以及 reset 后第一步的观测沿用了 `tracking_inference.py` 的做法，部分特权观测可能来自 reset 前的状态。
这一点**未核实**。它是对称噪声（复跑优于原跑的比例为 49.7%），所以本实验把它当作噪声底，
所有 T 的差异都远高于它。

**误区 4："z 余弦 0.93 很接近，所以 T 无所谓。"**
z 的接近程度不等于行为的接近程度，见推论 2。z_dim 为 256 且投影到 √256 的球面上，
0.93 的余弦对应 L2 距离约 6，对 actor 来说是可感知的差异。

**误区 5："动作差 0.2 很小。"**
这是 29 维归一化动作的 L2。换算到关节目标时要乘 5（`normalize_action_to`）× 0.25（`action_scale`）
× 各关节的 effort/kp（`action_rescale`），而且本实验没有记录动作本身的幅值，所以没法说它占动作的百分之几。
判断大小应以噪声底（0.024）为参照：它是噪声底的约 9 倍。

## 8. 局限与后续

- 只测了一个模型、一组 horizon（1 s）、起点步长 10 帧。
- 只测了滑动更新 z 的方式。**待做**：固定 z 执行 T 步，对比参考帧 t+1..t+T，
  回答"一个 chunk token 能否代表一段 T 帧动作"。
- 动作差没有相对量：可以在 rollout 中加记 ‖a‖。
- 噪声底的来源未核实：可以对比复跑 env 在 reset 后第一步的观测是否完全相同。
