# 实验：把 goal z 换成残差 VQ 的重建，策略还能跟住动作吗

- 日期：2026-10-20
- 脚本：`experiments/rvq_rollout.py`（复用 `experiments/rvq_capacity.py` 的码本与函数）
- 模型：`new_model_for_training_code_inference`
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作；训练 / 留出划分与 `latent_vq`、`rvq_capacity` 相同
  （留出 `fallAndGetUp1_subject5`、`jumps1_subject1`、`run2_subject1`、`walk2_subject1`）
- 原始结果：本目录 `metrics.json`、`per_motion.csv`，`rollouts.npz`（逐步数据）与 `jacobian.npz`（已 gitignore，只在本地）

## 1. 问题

`rvq_capacity` 显示 RVQ 的重建余弦远低于 actor 看起来需要的 0.98，但 actor 只对约 3 个方向敏感，
重建余弦不一定能代表执行效果。这里直接测：**把 tracking 时每一步的 goal z 换成它的 RVQ 重建，机器人跟踪参考动作的效果损失多少？**

## 2. 设置

- **执行**：与 `z_to_motion` 相同。从参考帧 t 的状态出发，`model.act(mean=True)` 闭环 **100 步（2 s）**，
  第 k 步用第 t+1+k 帧的 z（或它的替代品）。每个动作每 50 帧取一个起点，共 8,762 个，其中留出动作 890 个。
  关闭域随机化、观测噪声和 termination。
- **15 个变体**，同一起点在相邻 env 中并排运行：

| 变体 | 第 k 步给 actor 的 z | 帧余弦（训练 / 留出） |
|---|---|---|
| base | 原始 goal z | 1 |
| rerun | 原始 goal z，复跑（噪声底） | 1 |
| frozen | 整个 rollout 一直用第 1 步的 z（**下界**：z 不再提供新信息） | — |
| previous_frame | 上一帧的 z（晚 20 ms） | 0.992 / 0.990 |
| nearest_other_motion | 训练集中另一个动作里 z 最近的那一帧的 z | 0.689 / 0.697 |
| pca128 / pca192 | 训练帧前 128 / 192 个主成分的重建（连续、无量化） | 0.867 / 0.824；0.952 / 0.925 |
| rkm256@2 / rkm256@8 | 残差 k-means，K=256，2 / 8 层（16 / 64 bit/帧） | 0.713 / 0.608；0.841 / 0.754 |
| rkm1024@4 / rkm1024@8 | K=1024，4 / 8 层（40 / 80 bit/帧） | 0.851 / 0.721；0.899 / 0.783 |
| chunk1_k256_h1024@1 / @2 | 现有 `LatentRVQVAE`（chunk 1），1 / 2 层（8 / 16 bit/帧） | 0.541 / 0.406；0.700 / 0.496 |
| chunk8_k256_h1024@2 | 现有 `LatentRVQVAE`（chunk 8），2 层（2 bit/帧） | 0.643 / 0.447 |

- **第 0 步的雅可比**：在基线 env 的观测上算 J = ∂a/∂z，记录每个变体的 z 误差方向的增益 ‖J·e‖/‖e‖，
  与随机方向的增益（0.033）比较，看量化误差是否恰好落在 actor 敏感的方向上。

运行命令（RTX 5070 上约 18 min；需要先跑 `rvq_capacity` 生成 `codebooks.npz`）：

```bash
uv run python -m experiments.rvq_rollout --model-folder new_model_for_training_code_inference
```

## 3. 指标定义

沿用 `tracking_window` / `z_to_motion` 的定义。

| 指标 | 含义 |
|---|---|
| `ref@k` | 第 k 步与参考帧的 30 个刚体平均距离（m），世界坐标，含根漂移 |
| `ref_local@k` | 同上，两边各减去根节点位置后的距离（只看姿态） |
| `body_base@k` | 第 k 步与 base rollout 的刚体平均距离（m） |
| `dof_ref` | 100 步平均的关节角 RMSE（rad） |
| `lost` | 100 步内任一步 `body_ref` > 0.5 m 的比例 |
| 差距恢复率 | (lost_frozen − lost_变体) / (lost_frozen − lost_base)。1 = 和原始 z 一样好，0 = 和冻结 z 一样差 |
| gain | 第 0 步 z 误差方向的一阶增益 ‖J·e‖/‖e‖ |

注意 `lost` 的基线本身就很高（训练 24%、留出 38%），因为 2 s 内世界坐标的根漂移会累积，0.5 m 的阈值对快速动作偏紧。
它适合做变体之间的相对比较，不代表真实的失败率。

### 4.5 误差方向

- 随机方向的一阶增益 0.033，σ1 = 0.461（与 `z_to_motion` 一致）。
- 所有替代品的误差方向增益都在 0.024–0.035 之间，与随机方向相当：量化误差既没有特别避开、也没有特别集中在 actor 敏感的方向上。
  rkm1024@8 的误差增益（0.027）低于 pca192（0.035）。
- 逐起点看，在所有替代变体上，Spearman(1 − z_cos, body_base@100) = 0.55。

## 5. 推论

1. **actor 比重建余弦所暗示的宽容得多。** rkm1024@8 的帧余弦只有 0.90，却恢复了训练动作上 96% 的 frozen→base 差距
   （lost 25.3% 对 base 24.0%），姿态误差 `ref_local@100` 只多 0.14 cm。
   `z_to_motion` 中余弦 0.9 的随机扰动会使轨迹差约 9 cm，但跟踪质量只略降，这里也一样：轨迹与 base 分叉（14 cm），但仍然跟着参考走。
2. **但要达到"几乎无损"，需要很高的 bit 率。** 训练动作上：16 bit（rkm256@2）恢复 67%，40 bit 91%，64 bit 90%，80 bit 96%。
   留出动作上最好的配置也只到 88%，而且从 40 bit 到 80 bit 几乎不再提升（0.876 → 0.882），说明新动作上的瓶颈是泛化，不是码本容量。
3. **现有的 `LatentRVQVAE` 是最弱的一环。** 同样 16 bit，learned chunk1 恢复 58%（训练）/ 55%（留出），
   不如无 encoder 的残差 k-means（67% / 69%），甚至不如"直接拿另一个动作里最近的一帧"（67% / 80%）。
   只用第 1 层 token 时只恢复 23% / 38%，接近冻结 z。
4. **"从真实帧里检索"比"解码出的重建"更稳。** 在留出动作上，nearest_other_motion 的帧余弦（0.695）和 learned chunk1@2（0.494）
   相差很大，但恢复率是 80% 对 55%。PCA192 的余弦（0.925）高于 rkm1024@8（0.782），恢复率却更低（82% 对 88%），
   误差增益也更高（0.035 对 0.027）。说明除了余弦大小，误差的"结构"也有影响：落在数据分布上的 z 比被截断或解码出的 z 更容易执行（未核实）。
5. **重建余弦只是行为的粗略代理。** 逐起点 Spearman 只有 0.55；变体间的排序大体与余弦一致，但有例外（推论 4）。
   评估 tokenizer 时应以闭环指标为准，至少以首步动作差（open-loop action gap）为准，而不是 z 的余弦。
6. **快速、复杂的动作损失最大。** fight、fightAndSports、dance 用 16 bit token 时 lost 增加 15–20 个百分点；walk 和 sprint 几乎不受影响
   （walk 的 rkm256@2 只比 base 多 0.7 个百分点）。留出的 walk2 却损失明显（18.6% → 29.5%），说明即使是 walk，新动作的泛化也不够。
7. **z 中的大部分信息在 2 s 内确实有用。** frozen（只用第 1 步的 z）把 lost 从 24% 推到 58%（留出 38% → 74%），
   说明 actor 确实在逐帧读取 z 里的新信息，任何 tokenizer 都必须把这部分信息保留下来。

## 6. 残差 VQ 可行性的总体判断（结合 `rvq_capacity`）

- **作为 z 的忠实压缩：不可行。** z 几乎满秩，80 bit/帧在新动作上也只能还原到余弦 0.78，离"差一帧"的 0.99 很远。
- **作为 actor 的输入：在高 bit 率下勉强可行，低 bit 率下明显有损。** 40–80 bit/帧的残差码本能保住约 90%（训练）/ 88%（留出）的跟踪能力；
  VQ-BeT 式的 2 层 × 256（16 bit）只保住 55–70%。
- **现有的 tokenizer 需要改进**：它在同等 bit 下不如无 encoder 的残差 k-means，也不如直接检索真实帧。
- **值得尝试的方向**（未验证）：
  1. 用闭环或首步动作差作为 tokenizer 的训练 / 选择目标，而不是 z 的 L1 或余弦；
  2. 码本直接取真实帧的 z（检索式 token），或对 rkm 的重建再做一次"投影到最近的真实帧"；
  3. 粗层 token 负责"做什么动作"（第 1 层平均持续 12 帧、很好预测），细节交给连续残差或 actor 自身，而不是加更多离散层；
  4. 换用更平滑的 T=8 tracking z 再测一遍率失真和闭环结果。

## 7. 误区澄清

**误区 1："lost 24% 说明原始 z 的跟踪就很差。"**
这是 2 s、世界坐标、0.5 m 阈值下的数字，根漂移会累积。它只用于变体之间的比较；`ref_local@100`（只看姿态）基线只有 7.6 cm。

**误区 2："rkm1024@8 和 base 的 lost 只差 1.3 个百分点，所以 VQ 没有损失。"**
那是训练动作，相当于记忆。留出动作上差 4.3 个百分点，而且与 base 的轨迹在 2 s 后平均分叉 25 cm。

**误区 3："帧余弦越高，跟踪越好。"**
大体如此，但不绝对：nearest_other_motion 余弦更低却比 learned chunk1@2 好；pca192 余弦更高却不如 rkm1024@8（推论 4）。

**误区 4："chunk8 每帧只用 2 bit，却和 chunk1 的 16 bit 差不多，所以 chunk 更划算。"**
两者都只恢复了约一半的差距（训练 62% 对 58%，留出 48% 对 55%），都属于明显有损的一档，不能据此说 chunk 划算。

## 8. 局限与后续

- 只测了一个模型、T=1 的 goal z、2 s horizon，并且是在参考状态下开始的跟踪（不是从 token 生成新动作）。
- 留出集只有 4 个动作、890 个起点，按动作看的数字噪声较大。
- 推论 4 中"落在数据分布上的 z 更容易执行"的解释未核实。
- 没有测试在量化 z 上微调 actor 的方案；那可能是让低 bit 率 token 可用的最直接途径。
