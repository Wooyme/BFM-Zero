# 实验：可控地改变 goal z，策略执行出来的动作变化多少

- 日期：2026-10-20
- 脚本：`experiments/z_to_motion.py`（单测 `tests/test_z_to_motion.py`）
- 模型：`new_model_for_training_code_inference`（z_dim 256，z 在半径 √256 = 16 的球面上）
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作
- 原始结果：本目录 `metrics.json`、`per_motion.csv`、`jacobian.npz`（3 MB）、`rollouts.npz`（逐步数据，240 MB）。
  两个 npz 已 gitignore，只在本地。脚本默认就输出到本目录

## 1. 问题

`tracking_window` 发现 z 余弦 0.93 时执行结果已明显不同；`motion_to_z` 发现从参考动作看，z 近基本等于动作近。
所以要问 actor 这一侧：**z 改变多少、往哪个方向改变，动作和轨迹会变多少？** 是不是所有方向都一样敏感？

## 2. 设置

- **z**：每帧 goal z（T=1），`project_z(B(next_obs[f]))`，速度保留，与 `motion_to_z` 和当前 `latent_vq` 一致。
- **起点与执行**：与 `tracking_window` 相同。参考帧 t 的根状态和关节状态 reset，`model.act(obs, z, mean=True)` 闭环 50 步（1 s），
  z 按 tracking 方式滑动（第 k 步用 z(t+1+k)）。每个动作每 50 帧取一个起点，共 **8,802 个起点**。
  关闭域随机化、观测噪声和所有 termination（运行时断言没有 env 被重置）。
- **扰动**：`z' = c·z + √(1−c²)·|z|·û`，û 是方向 u 去掉 z 分量后的单位向量。这样 `cos(z', z) = c` 精确成立，且 z' 仍在球面上。
  u 在一次 rollout 内固定，每一步对新的 z 重新正交化。余弦 c 取 0.9999、0.999、0.995、0.98、0.95、0.9、0.8，
  对应的 z 的 L2 变化量为 0.23、0.72、1.6、3.2、5.1、7.2、10.1。
- **4 种方向**：
  - `random`：各向同性高斯方向
  - `data`：指向另一个动作中随机一帧的 z（数据分布内的方向，相当于向那帧 slerp）
  - `sensitive`：第 0 步 actor 雅可比 J = ∂a/∂z（29×256，限制在球面切空间上）的最大奇异向量
  - `null`：随机方向投影到 J 的零空间（J 秩 ≤ 29，256 维中至少 226 维在一阶近似下不影响动作）
- **并排对照**：每个起点有 30 个变体，在相邻 env 中从同一状态出发：基线、基线复跑（噪声底），以及 4 种方向 × 7 个余弦。

运行命令（RTX 5070 上约 18 min）：

```bash
uv run python -m experiments.z_to_motion --model-folder new_model_for_training_code_inference
```

## 3. 指标定义

沿用 `tracking_window` 的定义，`*_base` 都是与同一起点的基线 rollout 比较。

| 指标 | 含义 |
|---|---|
| `open_loop_action` | 第 0 步动作与基线动作之差的 L2（29 维归一化动作） |
| `pred_open_loop` | 一阶预测 ‖J·Δz‖，J 在基线 env 的第 0 步观测和 z 上计算 |
| `action_base` / `action_rel` | 闭环 50 步的平均动作差 / 再除以基线动作的平均模长（1.854） |
| `body_base@k` | 第 k 步时与基线 rollout 的 30 个刚体平均位置距离（m） |
| `body_ref` / `ref@50` | 与参考帧的刚体平均距离（世界坐标），对 50 步取平均 / 只看第 50 步 |
| `lost` | 50 步内任一步 `body_ref` > 0.5 m 的比例 |
| 行为等效余弦 | 该方向上让 `body_base@50` 平均达到 5 cm 所需的余弦（在 1−c 上线性插值） |
| gain | 单位切向量 û 的一阶增益 ‖J·û‖ |

## 5. 推论

1. **actor 对 z 极其敏感，而且没有"安全余弦"。** 即便 c = 0.9999（z 只变了 0.23，相当于每维约 0.014），
   random 方向 1 s 后的轨迹差也高于噪声底（1.3 cm 对 1.0 cm）；c = 0.98 时达到 5 cm，c = 0.9 时约 9 cm。
   响应随余弦平滑、单调地增大，没有一个阈值以下"几乎不变"。
2. **敏感度强烈依赖方向。** 同样达到 5 cm：sensitive 方向只需 c = 0.9995，random 与 data 约 0.98，null 约 0.95。
   在很小的扰动下（c = 0.9999），sensitive 方向的首步动作差约为 random 的 4 倍（扣除噪声底后约 5.6 倍）。
   J 的有效维度只有约 3：256 维的 z 中，只有少数几个方向能让动作大幅改变。
3. **"一阶无感"的方向并不真的无感。** null 方向的一阶预测为 0，但实际首步动作差随扰动增大而稳定增长，
   c = 0.8 时的轨迹差（10 cm）只比 random 小约 25%。说明 actor 的线性近似只在很小的邻域内成立（推论 4），
   不能用 J 的零空间来"安全地"移动 z。
4. **一阶近似只在极小范围内有效。** sensitive 方向在 c = 0.9999 时实测与预测接近（0.126 对 0.106），
   到 c = 0.999 预测已高估 1.6 倍，c = 0.8 时高估约 9 倍（tanh 饱和与网络的非线性）。
   random 方向则相反：小扰动时实测（扣除噪声底）约为预测的 2–3 倍，大扰动时两者接近。
5. **数据方向比随机方向更敏感一些。** c ≤ 0.95 后，data 方向的轨迹差和丢失率都明显高于 random
   （c = 0.8 时 20 cm 对 13 cm，lost 13.8% 对 8.3%）。推测是因为朝另一帧的 z 走，意味着让 actor 去做另一个真实动作，
   而随机方向的大部分分量落在 actor 不太关心的维度上（未核实）。
6. **T=8 与 T=1 的差异方向是一个"普通"方向。** 它的一阶增益（0.028）约为 random 的 0.93 倍，
   远小于 sensitive 方向。所以 `tracking_window` 中 0.927 余弦带来 6.4 cm 的差异，不是因为恰好落在敏感方向上，
   而是 actor 对任意方向都这么敏感（random 在 c = 0.95 和 0.9 时分别为 7.1 cm 和 9.4 cm，与之相符）。
7. **轨迹分叉了，跟踪质量却只略降。** random 0.95 时与基线的轨迹差为 7.1 cm，但第 50 步对参考的误差只从 20.0 cm 增加到 21.1 cm，
   只有 61.5% 的起点变差。也就是说，在 c ≥ 0.95 时，z 的扰动主要把机器人带到另一条差不多好的轨迹上，而不是明显变坏。
   c ≤ 0.9 或沿 data / sensitive 方向时，跟踪误差和丢失率才明显上升。
8. **偏离程度主要由状态决定，而不是由 J 决定。** 逐起点看，偏离呈长尾（random 0.95：中位数 5.5 cm，q99 28 cm）。
   这和复跑的偏离相关（Spearman 约 0.3），而与该起点的 σ1 无关（0.05）。偏离大的往往是本身就不稳定的状态
   （复跑也有 1% 的起点偏离超过 10 cm），一阶敏感度无法预测哪些起点会分叉。
9. **快速动作更敏感。** run 在 random 0.95 时偏离 9.4 cm，walk 和 sprint 约 6 cm；fallAndGetUp 的 σ1 最小（0.36），偏离也最小。

## 6. 给人看的结论

- 机器人对 z 非常敏感：z 的余弦只降到 0.98，1 秒后的动作就平均差约 5 厘米；降到 0.9，差约 9 厘米。没有"足够接近就一样"的余弦阈值。
- 但不同方向差别很大：有极少数几个方向，z 只要动一点点（余弦 0.9995）就有同样效果；也有很多方向不太敏感。
- 动作虽然变了，但只要余弦 ≥ 0.95，跟踪参考动作的效果只是略差，更像是"换了一种同样合理的做法"。
- 结合 `motion_to_z`："z 差异不大时动作也可能差异很大"，原因在 actor 一侧，而不是 z 把不同动作编码到了一起。
- 对 `latent_vq` 的启示：量化误差即使只有余弦 0.98 的量级，执行时也会产生厘米级的差异；
  而且误差在敏感方向上的分量比整体余弦更重要。可以考虑用 actor 的敏感度（如 J 的前几个奇异方向）加权量化误差。

## 7. 误区澄清

**误区 1："余弦 0.99 已经很接近了。"**
z 在半径 16 的球面上，余弦 0.99 对应 L2 约 2.3，c = 0.98 对应 3.2。对这个 actor 来说，这已经足以让 1 s 后的轨迹平均差 5 cm。
`motion_to_z` 中，余弦 0.98 大约是参考动作相隔 1–2 帧的差距。

**误区 2："J 的零空间里移动 z 不会影响动作。"**
只在无穷小的范围内成立。实测 c = 0.95 时，null 方向的首步动作差为 0.113，是噪声底的约 5 倍（推论 3）。

**误区 3："轨迹差 7 cm 说明跟踪变差了 7 cm。"**
`body_base` 是与基线 rollout 的距离，不是与参考的距离。基线本身在第 50 步离参考约 20 cm，
扰动后的轨迹偏向别的方向，对参考的误差只增加约 1 cm（推论 7）。

**误区 4："open_loop_action 扣掉噪声底就是 z 的纯效应。"**
文中"扣除噪声底"用的是 √(实测² − 噪声²)，假设两者独立相加，这只是粗略估计。噪声底本身（同一 z 首步动作差 0.023）
说明各 env 在 reset 后第一步的观测并不完全相同，原因与 `tracking_window` 误区 3 相同，**未核实**。

**误区 5："sensitive 方向的预测值 4.5 说明动作会差 4.5。"**
那是一阶线性外推。actor 输出经过 tanh，动作每维都在 [−1, 1] 内，实际首步动作差只有 0.52（推论 4）。

## 8. 局限与后续

- 只测了一个模型、T=1 的 goal z、1 s horizon、起点步长 50 帧。
- 扰动方向在一次 rollout 内固定；sensitive 和 null 方向只在第 0 步的状态上计算，之后状态变化，它们不再是最敏感 / 无感方向。
- 雅可比只算了均值动作对 z 的导数，没有分析它在时间上的变化，也没有分析各奇异方向在 z 空间中的语义（例如是否对应速度）。
- 可以把 `motion_to_z` 的 `collisions.csv` 中的帧对拿来执行，直接验证"z 近、动作远"的帧对执行起来差多少。
- 噪声底的来源仍未核实。
