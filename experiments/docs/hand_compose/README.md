# 实验：行走 + 手到位，能否用两张相加的 z 表代替一张乘积 vocab

- 日期：2026-10-20
- 脚本：`experiments/hand_compose.py`（单测 `tests/test_hand_compose.py`）
- 模型：`new_model_for_training_code_inference`（z_dim 256，z 在半径 16 的球面上）
- 数据：`humanoidverse/data/lafan_29dof` 全部 40 个动作。起点只取 12 个 walk 动作；`walk2_*`（3 个）为留出动作，
  不进入 D_edit 和检索池（但 BFM-Zero 本身训练时见过它们）
- 原始结果：
  - 主实验：本目录 `metrics.json`、`per_variant.csv`，`rollouts.npz`、`tables.npz`（已 gitignore，只在本地）
  - 追加实验（`delta` 来源）：`delta/` 子目录，文件相同

## 1. 问题

holosoma 的 `BFMCodebookAction` 只从一张 z 表（`multi4k`）里选 token。如果"行走时手到某个位置"也靠枚举 token，
vocab 要按 行走状态 × 手的位置 **相乘**地增长。`rvq_capacity` / `rvq_rollout` 已经说明把 z 压成离散 token 损失很大。

这里试另一条路：**两张离线算好的表相加**，z = project(z_walk[k] + λ·z_hand[m])，让 vocab 按 N + M 增长。
holosoma 一侧仍然是纯 RL，只多选一个下标 m。具体回答：

1. 这样组合出的 z，能不能让手到目标附近，同时保持行走？
2. z_hand 用什么数据算最好：训练 replay buffer，还是把行走帧手臂改成 IK 解得到的编辑数据 D_edit？
3. 和"真的有这样一帧"（编辑后的帧本身、或检索到的真实帧）比，差多少？

## 2. 设置

- **手的目标**：一只手腕（`*_wrist_yaw_link`）相对骨盆的位置，在 heading 坐标系（只去掉 yaw）下表示。
- **目标网格（第二张 vocab）**：
  - 取 10 cm 的格子。在直立的训练帧上随机摆手臂（4 个关节在限位内均匀采样，20 万次），
    被手腕到达至少 5 次的格子组成网格：左手 598 格，右手 595 格。
  - `in` 格子：直立训练帧中该手腕落在格内至少 20 次（左 262、右 255）。
  - `out` 格子：可达但数据里一次都没有（左 189、右 198）。
- **D_edit**：
  - 来源：9 个训练 walk 动作，按 50 Hz 的参考帧切成 100 帧（2 s）一段，切两遍，每遍起点随机偏移。
  - 编辑：每段随机选一只手和一个可达格子内的随机目标。用 IK 把该手的肩 3 + 肘 1 个关节解到目标（腕关节不变）。
    IK 是可微 FK 上的 Adam，中间帧多起点求解，其余帧从中间帧的解出发并向它正则，保证手臂平滑移动。
  - 速度：用运动库的同一套 `fk_batch(return_full=True)` 在整段上差分（带高斯滤波），关节速度为前向差分。每段两端各丢 5 帧。
  - 结果：194,850 帧，IK 误差均值 7.0 cm，p95 21.7 cm。误差主要来自 `out` 格子：从行走的躯干姿态够不到。
- **z_hand**：
  - 奖励为 r = exp(−‖wrist − target‖² / 2·0.05²)，用 `FBModel.reward_wr_inference` 同样的加权，即 w = r·softmax(10 r)。
  - 每个来源、每只手、每个格子算一个向量。手腕位置直接从 `privileged_state` 的对应 3 列切出，已对 FK 核对过。
  - 来源：

| 来源 | 数据 | 组合方式 |
|---|---|---|
| `buf` | 训练 replay buffer（`train_reduced`，100 万条） | project(z_walk + λ·project(Σ w B)) |
| `edit` | D_edit 的 B | 同上 |
| `buf+edit` | 两者合并 | 同上 |
| `delta`（追加实验） | D_edit 成对的差：ΔB = B(编辑帧) − B(原帧) | project(B_walk + λ·Σ w ΔB / Σ w)，加在未投影的 B 上，λ = 1 约等于编辑帧本身 |

- **执行**：
  - 起点：从 walk 参考帧 t 的状态出发，每 100 帧取一个，共 1,435 个；其中训练 1,081 个、留出 354 个，`in`、`out` 各半。
  - 每个起点随机选一只手和一个目标：在对应档的格子中随机取一格，再在格内均匀取点。
  - 闭环跑 150 步（3 s），第 k 步的 z_walk 是参考帧 t+1+k 的 T=1 goal z。关闭域随机化、观测噪声和 termination。
- **变体**（同一起点并排跑）：

| 变体 | 第 k 步的 z |
|---|---|
| `walk` | 参考帧的 goal z，不管手（基线） |
| `add[src,λ]` | 组合 z，z_hand 取目标所在格子的表项，λ ∈ {0.25, 0.5, 1, 2, 4} |
| `exact[src,λ]` | 同上，但对精确目标现算 z_hand，用来衡量网格离散化的损失 |
| `edit_track` | 把参考段的手臂按同样方法 IK 到目标后，编辑帧自身的 goal z（**诊断用的上限**，不部署） |
| `retrieve` | 每步在所有直立训练帧中检索最近的一帧，取它的 goal z。代价 = 手位差/5 cm + 速度差/0.15 m/s + 腿关节 RMSE/0.1 rad（相当于一张**乘积 vocab**） |

- **自检**：
  - 参考帧经 FK 的刚体位置与存储值最大差 0.6 mm。
  - 不编辑时，整条编辑流水线（FK、差分速度、B）算出的 z 与 `Reference` 的 z 余弦平均 0.99998（最小 0.99986）。
  - `privileged_state` 中手腕列与 FK 相差 0.5 mm。
  - 两次独立运行中相同的变体，手位误差相差 ≤ 0.5 cm（主实验与追加实验都有 `walk`、`add[edit,*]`、`edit_track`、`retrieve`）。

运行命令（RTX 5070，512 env；主实验约 28 min，追加实验约 12 min。1024 env 时 PhysX 显存不足，会冻结仿真）：

```bash
uv run python -m experiments.hand_compose --model-folder new_model_for_training_code_inference --num-envs 512
uv run python -m experiments.hand_compose --model-folder new_model_for_training_code_inference --num-envs 512 \
    --sources edit delta --no-exact --output experiments/docs/hand_compose/delta
```

## 3. 指标定义

| 指标 | 含义 |
|---|---|
| `hand_err` | 最后 1 s（50 步）手腕与目标的平均距离（m），heading 坐标系，相对骨盆 |
| `hand_gain` | `walk` 的 `hand_err` 减去该变体的（m），越大越好 |
| `vel_err` | 最后 1 s 根部平均水平速度（heading 坐标系）与参考的差（m/s） |
| `yaw_err` | 最后 1 s 平均 yaw 角速度与参考的差（rad/s） |
| `leg_dof_ref` | 12 个腿部关节相对参考的 RMSE（rad），150 步平均 |
| `leg_dof_base` | 12 个腿部关节相对 `walk` 变体同一时刻的 RMSE（rad）：手的改动把步态改变了多少 |
| `fall` | 150 步内骨盆高度低于 0.5 m 的比例 |
| `drift` | 下半身 16 个刚体的世界坐标误差超过 0.5 m 的比例。3 s 的漂移会累积，只用于变体间比较 |
| `z_cos` | 与 `walk` 变体同一步 z 的余弦 |

## 5. 推论

1. **没有任何相加的配置达到判据。** 判据是手位误差 < 5 cm，且行走不明显变差。
   最好的 `in` 手位误差约 12 cm（`add[edit,4]`），但速度误差从 0.15 增大到 0.45 m/s。
   基线的手离目标约 37 cm（`in`）和 60 cm（`out`）。
2. **相加有明确的"手 ↔ 行走"取舍，λ 越大手越准、走得越差。** 以 `in`、训练动作为例：
   - 速度误差只增加 ≤ 0.03 m/s 时，最多拉近 4–11 cm：`add[buf,0.5]` 10.8 cm，`add[delta,1]` 8.4 cm。
   - 要拉近 20 cm 以上，速度误差就要到 0.3–0.45 m/s，`leg_dof_base` 也到 0.2 rad 以上，步态已经明显改变。
3. **buffer 来源的 z_hand 会让机器人摔倒，编辑数据的不会。** `add[buf,4]` 的 fall 在 `in` 为 22%、`out` 为 49%；
   `add[edit,4]` 只有 9–10%，`add[delta,*]` 始终在 7–8%，与基线相当。
   推测 buffer 里"手在这个位置"的状态大多不是行走（站立、舞蹈、倒地等），它们的 B 把 z 拉向别的动作；
   D_edit 中所有状态都是在走路。这一解释未核实。
4. **成对的 `delta` 在小 λ 下取舍最好，但上限低。** 速度代价相同时，`delta` 拉近的距离最多，例如 λ = 1 时以 +0.02 m/s 换来 8 cm。
   但 λ 从 2 增加到 4 时手不再更近（23 cm → 25 cm），速度却变差很多。
   可能是因为 ΔB 是许多不同行走帧的平均差，只有一部分对当前帧适用。
5. **"真的有这样一帧"时，效果明显更好。** `edit_track`（编辑帧本身的 goal z）和 `retrieve`（最近真实帧）都把手拉近约 23–25 cm（`in`），
   速度误差只增加约 0.05 m/s，fall 不变。达到同样的手位，相加需要多付约 0.25 m/s 的速度误差。
   所以瓶颈主要在**线性相加**这一步，而不是 actor 做不出"边走边伸手"。
6. **但即使有这样一帧，手也只到 11–13 cm，到不了 5 cm。** `edit_track` 的 IK 残差只有 2.8 cm，
   剩下约 10 cm 是 actor 跟踪逐帧 goal z 时本身的误差。这是 T=1 goal z 跟踪的精度上限，与组合方式无关。
7. **乘积 vocab 确实很稀疏。** 检索池（全部直立训练帧）中，同时满足手位和速度的帧在 `in` 目标上只有 9%，`out` 上几乎为 0。
   但检索到的"大致相近"的帧（手位差约 13 cm）执行起来，与精确编辑出的帧差不多好（推论 5）。
8. **网格的分辨率不是问题。** 精确目标与格子中心的 z_hand 结果相差 < 1.4 cm，10 cm 的格子足够。

## 6. 给人看的结论

- 把"走路的 z"和"手到某处的 z"直接相加，手确实会往目标去，但加得越多，走路越不像原来的样子（速度偏差从 0.15 增大到 0.3–0.45 m/s）。
  没有一个设置能同时做到"手差 5 cm 以内"和"照常走路"。
- 用"边走边把手臂摆到目标"这样合成的数据来算手的 z，比用训练数据算的要安全得多：几乎不增加摔倒。
- 如果直接给机器人"一帧真的在边走边伸手"的目标，它能做得好得多：手近了约 24 cm，走路几乎不受影响。
  问题出在"两个 z 直接相加"这一步，而不在机器人做不到。
- 即使目标完美，用逐帧 goal z 跟踪，手也只能到 10 cm 左右，要更准需要别的手段（例如在 RL 里直接奖励手位）。

## 7. 误区澄清

- **"相加能走到 12 cm，所以差不多可行"**：12 cm 只出现在 λ = 4，这时速度误差是基线的 3 倍，步态已经变了（`leg_dof_base` 0.27 rad）。
  要比较的是同样速度代价下的手位，而不是单看手位。
- **"`delta` 余弦更高，所以更好"**：`delta` 的 z 与 `walk` 余弦更高，只说明它改动 z 少。
  它在小 λ 下取舍最好，但能把手拉近的最大距离也最小。
- **"`out` 目标做不好是组合的问题"**：`out` 目标的 IK 残差平均 10.8 cm，D_edit 中 58% 的 `out` 格子没有样本，
  `edit_track` 也只到 29 cm。很多 `out` 格子从行走的躯干姿态根本够不到，网格的"可达"是用各种直立姿态估的。
- **`drift` 不是失败率**：3 s 的世界坐标漂移很容易超过 0.5 m，连 `walk` 都有 33%。失败看 `fall`。
- **留出动作不是 BFM-Zero 没见过的动作**：`walk2_*` 只是没进 D_edit 和检索池，模型训练时见过。

## 8. 局限与后续

- 只测了开环的 z 组合：z_walk 固定取参考帧，不会根据状态换。holosoma 中 RL 策略可以每步重选行走 token 来补偿速度偏差，
  闭环效果可能比这里好。这需要在 holosoma 里实际训练才能知道。
- 只测了 T=1 goal z、一个模型、3 s。λ 对所有格子、所有行走帧共用一个值，没有按格子或按 token 调。
- IK 只动肩和肘，腕关节保持原值；没有让腰部参与，所以很多 `out` 目标够不到。
- **下一步建议**（未验证）：
  1. **离线学一个非线性组合器** f(z_walk, 手目标) → z，用 D_edit 的成对数据（原帧 z、目标 → 编辑帧 z）监督训练。
     推论 5 说明 f 的上限就是 `edit_track`。holosoma 中策略仍只选 (k, m) 两个下标，动作空间按 N + M 增长，
     f 作为冻结的函数（或离线展开成 N × M 的表）使用，不需要在线解算。
  2. 在 holosoma 中用两个 categorical 头 (k, m) 加固定 λ（例如 `edit` 来源，λ = 1）做 RL，看闭环能否把速度偏差纠正回来。
  3. 若要到 5 cm 以内，需要在 RL 中直接奖励手位（例如 holosoma 的 wrist 任务），单靠 z 的组合达不到。
